# 14. VERY IMPORTANT — BANDWIDTH/COST OPTIMIZATION

The downloader must NOT consume unnecessary hosting bandwidth.

The most important architecture requirement is:

DO NOT proxy or permanently store every downloaded video through my application server unless absolutely necessary.

Design the download system so that:

1. Metadata requests are lightweight.
2. Processing is controlled.
3. Temporary files are deleted quickly.
4. No downloaded files remain on the server unnecessarily.
5. Temporary files have automatic cleanup.
6. Maximum file size is configurable.
7. Maximum processing duration is configurable.
8. Concurrent downloads are limited.
9. Per-IP rate limiting is implemented.
10. Abuse protection is implemented.
11. Failed jobs are cleaned up.
12. Orphaned files are automatically removed.
13. Server disk usage is monitored.
14. CPU-heavy yt-dlp processes are limited.
15. Memory usage is limited.

Where technically possible, use a streaming/direct-transfer architecture that minimizes unnecessary server-to-client duplication.

DO NOT sacrifice reliability or violate the supported platform's terms while optimizing bandwidth.

Add configurable environment variables for:

MAX_CONCURRENT_DOWNLOADS

MAX_FILE_SIZE

DOWNLOAD_TIMEOUT

TEMP_FILE_TTL

MAX_REQUESTS_PER_IP

MAX_CONCURRENT_JOBS_PER_IP

CLEANUP_INTERVAL
